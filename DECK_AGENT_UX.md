# Deck agent launch UX

User preferences confirmed on 2026-10-14:

- Keep Claude, Codex and Antigravity quick icons beside **+ Agent**.
- Clicking a sidebar worktree or folder workspace only selects it; never auto-open the agent menu. Adding a new agent starts from the quick icons or **+ Agent**. Preserve recovery of existing sessions.
- Clicking an icon opens the account list. Clicking a healthy account goes to the session picker. Flow: **Agent → Account → Session**. Offer **New session** and the chosen agent's history; workspace sessions first, with **View all sessions** and search. Choosing a session launches it immediately; no **Open CLI** confirmation step.
- Hovering or keyboard-focusing an account previews its usage in a panel **to the right**. Never place usage below the list where it hides other accounts.
- Account rows stay transparent when selected; use a check mark only. A light hover wash fades out when the pointer leaves. Never add a persistent gray fill or white outline.
- Opening the picker focuses the launch account, not the settings gear. Keep hover transitions short and CSS-only; respect reduced motion and avoid continuously animated decoration.
- Launch into a split **inside the existing terminal tab**, using the hovered pane or active pane. Keep the current CLI and account intact. Create an initial terminal tab only when there is no terminal pane to split.
- Header revision (2026-10-15, latest): show **provider logo → session title** only, as in the original header. Keep a single line with ellipsis and the full title on hover. Keep account/model/reasoning in hover details and CLI statuslines; do not repeat them inline. Preserve account selection, authentication, launch, restore and session behavior.
- Account identity stays pinned to the current PTY/provider session, including after prompt/title updates, completion, renderer reload and app restore. Never infer an existing CLI's account from the currently selected global account; consuming resume authorization must not remove its identity. Antigravity may fall back to logo + title if its actual account is not reported. Missing historical account bindings must remain explicit rather than guessed.
- Claude's root SessionStart model must survive turns and child events in the host status store. Subscribe to PostModelSwitch only on supported CLI versions (2.1.251+, [hook reference](https://code.claude.com/docs/en/hooks#postmodelswitch)); model updates must preserve the current turn state and never announce completion.
- Sidebar revision (2026-10-15): outline the entire selected worktree, not individual agent tabs. Keep agent rows compact with a proper provider logo, its state indicator, session name and the subagent badge. Hide inline model text in both sidebar display modes, including sleeping sessions; retain known model metadata on the logo hover. Reserve a fixed close-button slot so hovering never shifts or covers the title/model. Never guess a missing model from global defaults. If the user says "quay lại lúc đầu", revert ONLY this sidebar framing/layout to the preceding individual agent card design; preserve session, status, account/model, zoom, and other fixes.
- Existing local Claude panes without a launch account id may display the account whose managed projects directory contains the session's host-reported transcript path. Require a unique path match; never substitute the globally selected account or match remote transcript paths to local accounts. This is read-only header presentation.
- Per-account Claude launches must bring the existing global Orca lifecycle hooks into the chosen config directory before starting the CLI, preserving account-owned hooks/settings and the global account selection. Respect the agent-status hook toggle. Missing hooks must not be papered over by changing a sidebar icon.
- Sidebar layout baseline for a scoped rollback: `~/.local/state/orca-sidebar-worktree-frame/2026-10-14/deck-chrome-before.css`; revert only that sidebar style patch, not any status or session logic.
- Ctrl + mouse wheel zooms the text of the pane under the pointer only. Trackpads support two-finger pinch and Ctrl + two-finger scrolling. Plain scrolling stays unchanged. Keyboard zoom uses the focused terminal: Ctrl + `=` / `-` / `0` on Linux/Windows, Cmd equivalents on macOS. Batch wheel updates per animation frame; do not add an animation library or change Orca's whole-window scale.
- The chosen account applies only to the new CLI; never change the global account selection.
- The agent card **×** closes that exact agent pane through its execution host. Dismissing a retained history row only removes the history row. A failed remote close must remain visible as an error.
- Offer **Add account** and **Sign in again** for missing or revoked credentials. Antigravity currently uses the existing `agy` login.
- Apply and verify changes in the installed main Orca, keeping test windows hidden.
- In-process subagents use a compact **↳ active count** badge beside their parent, in both sidebar display modes. Hover, or activate with keyboard/click, to see names and current states on the right. Completed children stay under a collapsed **Completed** section in that popover; never render them as additional sidebar cards. Preserve the host's child states and activation of the parent pane. Keep independently launched child CLI panes actionable.
